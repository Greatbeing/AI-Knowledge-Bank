# ADR-0002：Reuse Before Build（复用先于重造）

- 状态：Accepted
- 日期：2026-11-28
- 适用范围：AI Knowledge Bank、Cognitive Engine 及其工程工作流

## 背景

AI 时代已经积累了大量由开发者和 Agent 创建的开源代码、工具、MCP Server、Skills、工作流、模型适配器和专业能力。若 AI 在每个任务中都默认从零生成代码或方案，就会重复已有劳动，增加开发成本、维护负担和安全风险，也无法有效利用全球开发者生态。

AI Knowledge Bank 的价值不应只是保存这些资产，而应让 AI 能够发现、理解、评估、组合和安全调用它们，最终完成用户任务。

## 决策

采用 **Reuse Before Build** 作为平台和 Cognitive Engine 的一级架构原则：

> Discover before integrate. Reuse before build. Compose before duplicate. Evidence before trust.

每个非平凡任务在进入新能力开发前，必须先完成候选能力发现与评估。决策结果统一为：

1. `reuse`：一个已有能力满足任务要求；
2. `compose`：多个已有能力通过明确接口互补，覆盖完整任务要求；
3. `adapt`：已有能力基本匹配，但需要明确的适配或扩展；
4. `defer`：存在潜在匹配能力，但许可证、安全、验证、维护状态或兼容性仍待核验；
5. `build_gap`：没有合适且可接受的已有能力，才允许设计新的能力；
6. `reject`：明确拒绝不兼容、不安全、许可证冲突或已废弃的候选资产。

## 决策门槛

候选能力至少从以下维度评估：

- 任务功能适配与输入输出覆盖；
- 版本、维护状态和运行时兼容性；
- 许可证、来源、作者归属和使用限制；
- 安全风险、权限范围、网络和文件访问；
- 测试、基准、独立评估和可复现证据；
- 接入、运行、维护、迁移和锁定成本。

Stars、下载量、README 自述和模型自评不能单独证明能力质量。许可证或安全状态未知时必须暂缓，不能默认通过，也不能借此把重复开发包装成必要的自研。

## 架构落实

- **AI Knowledge Bank** 负责来源连接、候选发现、标准化目录、来源追溯、许可证和验证证据展示。
- **Cognitive Engine** 负责将任务要求转化为能力需求，调用 Reuse Policy，在复用、组合、适配、暂缓和能力缺口之间作出可解释决策。
- **Runtime / Adapter Registry** 负责实际执行；发现和规划结果本身不授予执行权限。
- **Evaluation** 对复用方案与从零生成方案进行同任务对照，记录质量、成功率、成本、延迟、集成时间、维护负担和安全结果。

## 安全不变量

1. 发现不等于信任，信任不等于执行授权。
2. 不得因发现 GitHub 仓库、Prompt、Agent 或脚本而自动克隆、安装或执行。
3. 未核实许可证的候选保持 `review_required`。
4. 执行必须经过明确 Adapter、最小权限、隔离环境、预算限制和必要的人工审批。
5. 用户私有输入、文件、凭证和运行日志不得未经授权写入公开仓库。
6. `build_gap` 仅表示允许设计新能力，不表示允许部署、发布或执行。

## 衡量方式

核心指标包括：

- Capability Reuse Rate；
- 任务成功率和输出质量；
- 单次成功任务总成本；
- 端到端延迟和集成时间；
- 维护负担、回归率和安全事件。

Reuse Rate 是诊断指标，不是单独优化目标。若复用导致质量或安全下降，应选择更好的候选、适配、暂缓或自研。

`Capability Reuse Rate = 通过已有能力完成的成功任务数 / 全部成功完成的任务数`

## 代价与后果

**收益：** 减少重复开发；加快能力组合；把全球开发者成果转化为普通用户可用的生产力；使平台自身开发成为持续验证场景。

**代价：** 候选评估、许可证核验、接口适配、版本追踪和质量基准需要持续投入；第三方依赖也会带来供应链与维护风险。

## 首个验证场景

AI Knowledge Bank 和 Cognitive Engine 的后续开发本身就是 dogfooding 场景。每项重要工程任务应记录：

- 任务与验收标准；
- 搜索范围和候选来源；
- 采用、组合、适配、暂缓、拒绝或自研的决定及理由；
- 固定版本、许可证、安全和兼容性证据；
- 测试结果、质量、成本和后续维护情况。

不得把“搜索过 GitHub”当成完成复用验证；必须有实际采用或明确拒绝的证据。

## 复审条件

当任务评估数据表明复用长期无法改善质量、成本或速度，或许可证、供应链安全、数据驻留及平台执行边界发生重大变化时，重新审视本决策。
